# Подсказки

Открывай только после 20-30 минут честной попытки. Застрял — уровень 1,
ещё 15 минут — уровень 2.

## Уровень 1 — направление

Если завис TestTwoBigLocks — разбери по шагам, что делают две горутины,
которые одновременно берут по 6 слотов из 10 в твоей реализации.

Захват n должен быть атомарным: «проверил, что хватает, и забрал» —
под одним замком. А для ожидания «пока не хватит» нужен способ спать
до изменения состояния, не крутя цикл.

## Уровень 2 — конструкция

sync.Mutex для атомарности + sync.Cond для ожидания:
Lock(n): под мьютексом в цикле for cap-size < n { cond.Wait() }, затем size += n.
Release(n): под мьютексом size -= n, затем cond.Broadcast() — разбудить
всех ожидающих, чтобы перепроверили условие. Почему Broadcast, а не
Signal — хороший вопрос себе: ожидающие хотят разные n.

Такое решение проходит тесты, но не защищает от голодания: большой
Lock может ждать вечно за потоком маленьких (см. вопрос для разбора).
